ITEM-02: Fix Data Model - Separate Item from
Article/Instructions
Priority: CRITICAL
Route:
/dashboard2/
Screen Title: "Item Details" | Fields visible: Room (Kitchen), Item Type (Room Item), Purpose (How to
Clean), Tags (Kitchen, Room Item, Cleaning - 3/10), Article Title (How to Clean - Cabinets 23/100)
Current State
The screen shows "Article Title" field populated with "How to Clean - Cabinets" and indicates
"This name will appear on the QR code label". The UI conflates the concepts of Item and
Article, treating them as a single entity.
Problem - Data Model Misunderstanding
The application confuses the relationship between Items, Articles, and QR codes. This
fundamental data model error affects how content is organized and accessed.
Correct Data Model

Concept Description Example
Item A physical thing. Gets ONE QR code. Fridge, Oven, Cabinets
Article Instructions/content about an item. Multiple per item"H.ow to Clean", "How to Turn Off"
Purpose = Article Title (same thing) "How to Clean"
QR Code ONE per Item (not per article) Scan "Cabinets" fi see all articles
Required Changes
(cid:127) Item Name field should contain only the item (e.g., "Cabinets") — NOT "How to Clean -
Cabinets"
(cid:127) Article Title should equal the Purpose selected earlier (e.g., "How to Clean")
(cid:127) QR Code label must show Item Name only (e.g., "Cabinets")
(cid:127) When user scans QR for "Cabinets," app displays list of all articles for that item
(cid:127) Update database schema to enforce one-to-many relationship: Item fi Articles
