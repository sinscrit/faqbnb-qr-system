# PDF Request Parser Skill

**Created:** 2026-01-11
**Last Modified:** 2026-01-11 (removed LLM instructions section expectation)
**Purpose:** Parse extracted PDF text into structured feature requests

---

## Overview

This skill parses text extracted from FAQBNB Review PDFs into structured JSON for pipeline processing. The PDF is generated by another Claude skill and follows a predictable format.

---

## Input

Raw text extracted from a PDF file, passed as the content after this skill prompt.

---

## Expected PDF Structure

The input text will contain:

1. **Header Section**
   - Application Review title (e.g., "FAQBNB Application Review")
   - Session date/time
   - Reviewer identification
   - Optional: General context information about the project

2. **Request Sections** (1 or more)
   Each request follows this format:
   ```
   REQUEST N: [Title]
   Screen: [screen/component name]
   Priority: [CRITICAL | HIGH | MEDIUM | LOW]

   Current State
   [Description of current behavior]

   Problem
   [Description of the issue]

   Required Changes
   • [Change 1]
   • [Change 2]
   ```

3. **Summary Table**
   - Table listing all requests with priorities

4. **Pipeline Instructions**
   - Processing order recommendations
   - Dependency information

---

## Parsing Rules

### Request Boundaries
- Start: Line matching pattern `REQUEST \d+:` or `REQUEST \d+`
- End: Next request start, summary section, or end of document
- Delimiter: `---` separates requests

### Field Extraction

| Field | Pattern | Required |
|-------|---------|----------|
| ID | Number after "REQUEST" | Yes |
| Title | Text after "REQUEST N:" on same line | Yes |
| Screen | Line starting with "Screen:" | Yes |
| Priority | CRITICAL, HIGH, MEDIUM, or LOW | Yes |
| Current State | Text after "Current State" header | Yes |
| Problem | Text after "Problem" header | Yes |
| Required Changes | Bullet points (•, -, *) after "Required Changes" | Yes |

### Priority Normalization
- "CRITICAL" → "critical"
- "HIGH" → "high"
- "MEDIUM" → "medium"
- "LOW" → "low"

## Output Format

Return ONLY valid JSON in this exact structure:

```json
{
  "session": {
    "date": "YYYY-MM-DD",
    "time": "HH:MM",
    "reviewer": "string",
    "source_filename": "string (if available)"
  },
  "requests": [
    {
      "id": 1,
      "title": "Short descriptive title",
      "screen": "ComponentOrScreenName",
      "priority": "high",
      "current_state": "Description of current behavior...",
      "problem": "Description of the issue...",
      "required_changes": [
        "First required change",
        "Second required change"
      ]
    }
  ],
  "summary": {
    "total_requests": 5,
    "by_priority": {
      "critical": 1,
      "high": 2,
      "medium": 2,
      "low": 0
    }
  },
  "pipeline_instructions": "Any special processing instructions from the PDF"
}
```

---

## Processing Instructions

1. **Parse the header** to extract session date, time, and reviewer
2. **Identify all request sections** using the "REQUEST N:" pattern
3. **For each request:**
   - Extract the title from the REQUEST line
   - Find the Screen: line
   - Find the Priority: line and normalize to lowercase
   - Extract Current State section (until next header)
   - Extract Problem section (until next header)
   - Extract Required Changes as bullet point array
4. **Parse the summary table** if present for verification
5. **Extract pipeline instructions** from the final section
6. **Validate** that all required fields are present
7. **Output** the complete JSON structure

---

## Error Handling

If parsing fails:
- Return partial results with an "errors" array
- Include the raw text section that couldn't be parsed
- Set "success": false in the response

```json
{
  "success": false,
  "partial_requests": [...],
  "errors": [
    {
      "request_id": 3,
      "field": "priority",
      "message": "Could not parse priority value",
      "raw_text": "..."
    }
  ]
}
```

## Important Notes

1. **Output only JSON** - No explanatory text before or after
2. **Preserve exact text** - Don't paraphrase or modify the content
